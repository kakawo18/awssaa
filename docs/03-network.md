# 第3章 ネットワークおよびコンテンツ配信

> **章の一言**：VPCは「**誰が誰と通信できるか**（SG/NACL/ルート）」と「**インターネットに出るか出ないか**（IGW/NAT/エンドポイント）」の2軸。ELB・Route 53・CloudFrontは**L4かL7か／静的IPかDNSか／キャッシュするか**で切り分ける。

---

## 3.1 Amazon VPC

**一言で**：AWS上の自分専用の仮想ネットワーク。

**試験の核心**
- サブネットの各CIDRで**先頭4つ＋末尾1つの計5個のIPが予約済み**（/28なら使えるのは11個）。
- **パブリックサブネット＝インターネットゲートウェイ(IGW)へのルートがあるサブネット**。定義はルートテーブルであって名前ではない。
- プライベートサブネットからのアウトバウンドは **NAT Gateway**（パブリックサブネットに配置、**AZごとに置いて冗長化**）。
- IPv6のアウトバウンド専用は **Egress-Only インターネットゲートウェイ**（NATではない）。

**セキュリティグループ vs ネットワークACL（最頻出）**
| | セキュリティグループ | ネットワークACL |
|---|---|---|
| 適用先 | ENI（インスタンス単位） | サブネット単位 |
| 状態 | **ステートフル**（戻りは自動許可） | **ステートレス**（戻り＝エフェメラルポートの許可が別途必要） |
| ルール | **許可のみ** | 許可と**拒否**、番号の小さい順に評価 |
| 典型問題 | 通常のアクセス制御 | **特定IPをブロックしたい**＝NACL一択 |

**接続方式の見分け**
| 要件 | 答え |
|---|---|
| S3/DynamoDBにインターネットを経由せずアクセス、**無料** | **ゲートウェイ**VPCエンドポイント（ルートテーブルに追加） |
| その他のAWSサービス／SaaSにプライベート接続 | **インターフェース**エンドポイント（PrivateLink、ENI＋SG、有料） |
| 自社のサービスを他アカウントのVPCに公開 | PrivateLink（**NLB**＋エンドポイントサービス） |
| VPCを2つだけ、単純に接続 | VPCピアリング（**推移的ルーティング不可・CIDR重複不可**） |
| VPCが多数／オンプレも含めハブ＆スポークで集約 | **Transit Gateway** |
| オンプレ接続を**すぐ・安く**始めたい、暗号化必須 | Site-to-Site VPN（インターネット経由、2トンネル） |
| **一貫した帯域・低レイテンシ**の専用線（数週間〜必要） | Direct Connect（**既定では暗号化されない**→IPsec VPNやMACsecを併用） |
| DXの冗長化 | DX 2本（最高）／DX＋VPNバックアップ（安価な現実解） |
| 複数リージョンのVPCへ1本のDXから | Direct Connect Gateway |

**監視・その他**：VPCフローログ（**許可/拒否の記録は取れるがパケットの中身は見えない**→中身が要るならTraffic Mirroring）、Reachability Analyzer（到達性の原因特定）、AWS Network Firewall（ステートフルなL7フィルタ・ドメイン制限）。

## 3.2 Amazon ELB

**一言で**：トラフィックを複数ターゲットへ分散する。ASGとセットで高可用性の基本形。

**種類の見分け（ほぼこれだけで解ける）**
| 問題文のキーワード | 答え |
|---|---|
| HTTP/HTTPS、**パス・ホスト名・ヘッダーでルーティング**、コンテナ、Lambdaをターゲットに、Cognito認証、WAF | **ALB**（L7） |
| **TCP/UDP**、**静的IP／Elastic IP**、超低レイテンシ、数百万リクエスト/秒、**送信元IPを保持**、PrivateLink | **NLB**（L4） |
| **サードパーティ製のファイアウォール/IDS/IPSアプライアンス**を透過的に通す | **GWLB**（GENEVE） |
| 古い環境、EC2-Classic | CLB（レガシー、新規は選ばない） |

**試験の核心**
- ALBは**DNS名のみで固定IPがない**。固定IPが要件なら NLB か Global Accelerator。
- クロスゾーン負荷分散：**ALBは既定で有効（無料）／NLB・GWLBは既定で無効**（有効化するとAZ間転送料）。
- スティッキーセッション：ALBはCookieベース、NLBはソースIPベース。**そもそもセッションは外部化（ElastiCache/DynamoDB）するのが設計としての正解**。
- 登録解除の遅延（接続ドレイニング、既定300秒）＝スケールイン時に処理中のリクエストを切らない。
- ACM証明書で**SSL/TLSを終端**、SNIで1つのALBに複数ドメインの証明書。ALBでHTTP→HTTPSリダイレクト。
- クライアントIPはALBでは **X-Forwarded-For** ヘッダーで取得（NLBはそのまま見える）。
- ターゲットのヘルスチェックに失敗したインスタンスには振り分けない＝**ASGのヘルスチェックタイプをELBにする**とセットで効く。

## 3.3 Amazon Route 53

**一言で**：DNS＋ヘルスチェック＋ルーティング制御。可用性設計の要。

**ルーティングポリシーの見分け**
| 問題文のキーワード | ポリシー |
|---|---|
| 1つのリソースへ単純に | シンプル |
| **アクティブ/スタンバイ**、障害時に切り替え（DR） | フェイルオーバー（ヘルスチェック必須） |
| **最も低い遅延**のリージョンへ | レイテンシーベース |
| **ユーザーの国・地域**で振り分け（言語別サイト、法規制、地域ブロック） | 位置情報（Geolocation） |
| リソースの**位置とバイアス**で範囲を調整しながら寄せる | 地理的近接性（Geoproximity、Traffic Flow必要） |
| **A/Bテスト**、段階的な移行（20%だけ新環境へ） | 加重（Weighted） |
| ヘルスチェック付きで**複数のIPを返す**（簡易な負荷分散） | 複数値回答 |

**試験の核心**
- **エイリアスレコード**：ALB・CloudFront・S3・API Gatewayなどへ向け、**Zone Apex（example.com）に設定でき、クエリ料金が無料**。CNAMEはApexに設定できない。
- ヘルスチェックは**エンドポイント／他のヘルスチェックの計算（親子）／CloudWatchアラーム**の3種。プライベートリソースはCloudWatchアラーム経由で監視。
- プライベートホストゾーン＝VPC内だけで有効な名前解決。
- Resolver エンドポイント：**インバウンド**＝オンプレからAWSの名前を引く／**アウトバウンド**＝AWSからオンプレの名前を引く。
- TTLを短くしておくと切り替えが速いが、クエリ料金と負荷は増える。**DNSでのフェイルオーバーはTTL分の遅れが出る**（即時性が要件なら Global Accelerator）。

## 3.4 Amazon CloudFront / AWS Global Accelerator

### CloudFront
**一言で**：世界中のエッジロケーションでコンテンツをキャッシュし、配信を高速化するCDN。

**試験の核心**
- 静的だけでなく**動的コンテンツも高速化**（AWSバックボーン経由）。オリジンはS3・ALB・EC2・オンプレいずれも可。
- S3を**非公開のまま**配信するなら **OAC（旧OAI）**。バケットポリシーでCloudFrontのみ許可。
- コンテンツ保護：**署名付きURL＝個別ファイル／署名付きCookie＝複数ファイルをまとめて**。地理的制限で国単位のブロック。
- **WAFを付けられる**（ALB/CloudFront/API Gatewayが対象。NLBには付かない）。
- CloudFront用のACM証明書は**バージニア北部（us-east-1）で発行**する。
- オリジン障害に備える**オリジングループ（オリジンフェイルオーバー）**。
- コスト削減は**価格クラス**（100/200/All）で配信範囲を絞る。
- キャッシュの即時更新は**無効化（Invalidation）**だが、**ファイル名にバージョンを付ける方が推奨**。

**混同注意**：S3 Transfer Acceleration＝**アップロード**の高速化／CloudFront＝**配信（ダウンロード）**の高速化。

### Global Accelerator
**一言で**：2つの**固定Anycast IP**でユーザーを最寄りのAWSエッジに引き込み、AWSバックボーン経由で最適リージョンへ送る。

**CloudFrontとの見分け**
| 要件 | 答え |
|---|---|
| 静的/動的コンテンツを**キャッシュ**して配信、HTTP/HTTPS | CloudFront |
| **TCP/UDP**（ゲーム、IoT、VoIP、SIP）、キャッシュ不要 | Global Accelerator |
| **静的IPアドレスが必要**（ファイアウォールのホワイトリスト登録） | Global Accelerator |
| **リージョン障害時に数十秒で切り替えたい**（DNS TTLに依存したくない） | Global Accelerator |
| 段階的にリージョンへ流量を振る | Global Accelerator（トラフィックダイヤル） |
