# 第10章 その他のAWSサービス

> **章の一言**：AI系は**入力が何か（画像・音声・文書・テキスト）**で一意に決まる。移行系は**回線が細いか／DBか／ファイルか／既存プロトコルか**の4択。

---

## 10.1 Amazon API Gateway

**一言で**：APIの受付窓口。認証・スロットリング・キャッシュ・バージョン管理をマネージドで提供。

**試験の核心**
- **Lambdaを外部公開する標準の入口**。Lambdaを挟まずDynamoDBやS3など**AWSサービスを直接呼ぶ統合**も可能（コスト削減の選択肢）。
- **オーソライザー**：**Cognitoユーザープール**（JWT）／**Lambdaオーソライザー**（独自トークン・サードパーティ認証）／**IAM**（AWS内部の呼び出し）。
- **使用量プラン＋APIキー**＝顧客ごとのレート制限・課金。**スロットリング**でバックエンドを保護。
- **キャッシュ**（ステージ単位、TTL）でバックエンド負荷とレイテンシを削減。
- **ステージ＋カナリアリリース**で段階的デプロイ。
- **プライベートAPI**＝VPCエンドポイント経由のみ公開（インターネットに出さない）。
- CORSはAPI Gateway側で設定する（ブラウザからのエラーの定番原因）。

**種類の見分け**
| 要件 | 答え |
|---|---|
| APIキー、使用量プラン、キャッシュ、リクエスト検証、WAF、詳細な機能 | **REST API** |
| シンプルなプロキシで**低コスト・低レイテンシ**（機能は少ない） | **HTTP API** |
| **双方向通信**（チャット、リアルタイム通知） | **WebSocket API** |
| GraphQL、モバイルのオフライン同期・リアルタイム購読 | **AppSync**（→10.2） |

## 10.3〜10.8 機械学習・AIサービス（入力で判定する）

| 入力／要件 | サービス |
|---|---|
| **画像・動画**：顔検出/照合、物体・シーン検出、不適切コンテンツ、テキスト検出 | **Rekognition** |
| **スキャンした文書・PDF**からテキスト／**表・フォーム**を構造化抽出 | **Textract**（単なるOCR以上） |
| **音声 → テキスト**（文字起こし、字幕、話者分離） | **Transcribe** |
| **テキスト → 音声**（読み上げ） | **Polly** |
| **テキストの意味**：感情分析、キーフレーズ、エンティティ、言語検出、**PII検出** | **Comprehend** |
| 医療文書から**病名・投薬・検査値**を抽出（HIPAA対応） | **Comprehend Medical** |
| **翻訳** | **Translate** |
| 会話型ボット（音声・チャット） | **Lex**（Alexaと同じ技術） |
| **レコメンド**（この商品を買った人は…） | **Personalize** |
| **時系列の需要予測** | **Forecast** |
| オンライン**不正検知** | **Fraud Detector** |
| 社内文書の**自然言語での検索** | **Kendra** |
| 独自モデルの構築・学習・デプロイ | **SageMaker** |
| 生成AI（基盤モデル）のAPI利用 | **Bedrock** |

**典型の組み合わせ**：S3に画像アップロード → イベント通知 → Lambda → **Rekognition**で解析 → 結果をDynamoDBへ。コールセンター音声 → **Transcribe** → **Comprehend**で感情分析。

## 10.9 AWS Cost Explorer

- 過去**最大13か月**の利用傾向を可視化、**今後12か月の予測**、**RI/Savings Plansの推奨**。
- 「どのサービス・どのタグにいくらかかっているか」の分析＝Cost Explorer。

## 10.10 AWS Budgets

- **予算（コスト/使用量/RI・SP利用率）を設定し、超過または予測超過でアラート**（SNS/メール）。
- **Budgets Actions**＝しきい値超過でIAMポリシー適用やEC2/RDSの停止を自動実行。
- 「使いすぎを**事前に防ぎたい**」＝Budgets、「使った結果を**分析したい**」＝Cost Explorer。

## 10.11 AWS Cost and Usage Reports (CUR)

- **最も詳細な**請求データ（時間単位・リソース単位）をS3に出力。**Athena/Redshift/QuickSightで分析**。
- 「独自の詳細な課金分析・部門別配賦をしたい」＝CUR。

## 10.12 AWS Database Migration Service (DMS)

**一言で**：DBを**稼働させたまま**移行する。

- **同種移行**（Oracle→Oracle）も**異種移行**（Oracle→Aurora）も可。異種の場合は**AWS SCT（Schema Conversion Tool）**でスキーマ・ストアドを変換してからDMS。
- **CDC（継続的レプリケーション）**で差分を同期し、**ダウンタイムを最小化**して切り替える。
- ソース/ターゲットはオンプレ・EC2・RDS・S3・DynamoDB・Redshiftなど。

---

## 10.13 AWS DataSync

**一言で**：オンプレ↔AWS、AWS↔AWS間の**大量ファイル転送を自動化**（オンライン）。

- 対応：NFS、SMB、HDFS、自己管理オブジェクトストレージ ↔ **S3、EFS、FSx**。
- エージェントを立て、**増分・並列転送・スケジュール実行・検証**まで自動。専用プロトコルで高速。
- **Storage Gatewayとの違い**：DataSync＝**移行/定期同期（データを移す）**／Storage Gateway＝**日常運用（オンプレから使い続ける）**。

## 10.14 AWS Transfer Family

- **SFTP / FTPS / FTP / AS2** のエンドポイントをマネージドで提供し、保存先は **S3 / EFS**。
- 決め手は「**取引先が既存のSFTPクライアントを使い続ける**必要がある」「FTPサーバーの運用をやめたい」。

## 10.15 その他の移行と転送のサービス

| サービス | 一言で | 決め手 |
|---|---|---|
| AWS Snowball Edge | 物理デバイスでのデータ移送（数十TB〜PB） | **回線が細い／移送に数週間以上かかる**。エッジ処理も可能 |
| AWS Snowcone | 小型・軽量（8TB程度） | 現場・車載など過酷な環境の少量データ |
| AWS Snowmobile | トラック（〜100PB） | エクサバイト級のデータセンター移設 |
| AWS Application Migration Service (MGN) | サーバーの**リフト＆シフト**（ブロックレベル複製） | 「既存VMをそのままEC2へ、最小のダウンタイムで」 |
| AWS Application Discovery Service | 移行前のオンプレ資産調査 | 「何がどれだけ動いているか把握したい」 |
| AWS Migration Hub | 移行状況の一元追跡 | 複数ツールの進捗管理 |

**転送手段の見分け**
| 状況 | 答え |
|---|---|
| 100TBを回線で送ると数か月かかる | Snowball |
| 数TBをネットワーク経由で定期同期 | DataSync |
| DBを止めずに移行 | DMS（＋SCT） |
| 取引先がSFTPで置きに来る | Transfer Family |
| オンプレから使い続けたい（ハイブリッド常用） | Storage Gateway |
| 遠隔地からS3への**アップロードを高速化** | S3 Transfer Acceleration |
